# Настройка доступа для аудита (выполняет администратор портала)

1. Создать пользователя «Аудитор CRM» (не администратор). Права CRM: роль «только чтение» на нужные сущности;
   без прав записи в задачах и на Диске.
2. Под этим пользователем: Приложения → Разработчикам → Другое → Входящий вебхук. Scope: `crm`, `user_brief`,
   `department` (+ `task`, если нужен аудит задач). Сохранить URL в менеджере паролей.
3. На ПК аудитора задать переменную окружения на время сессии (не в файл!):
   PowerShell: `$env:B24_WEBHOOK_URL = "https://<портал>/rest/<id>/<код>/"`.
4. Проверка: `python b24_readonly.py scope` — убедиться, что нет лишних scope.
5. Шаблоны бизнес-процессов: администратор создаёт **временный** вебхук только со scope `bizproc`, используется
   в одной сессии, затем **удаляется**.
6. (Опционально) nginx: ограничить по IP только путь `/rest/<id_аудитора>/` — не весь `/rest/` (его используют
   мобильное приложение и интеграции).
7. Токен виден в журналах nginx/прокси (он в пути URL) — после аудита вебхуки удалить или перевыпустить.
