# QA сайта (НОВАПРОМ)

**Обязательно после любых изменений сайта.** Проверку выполняет субагент `website-qa`, не тот, кто вносил изменения.

## Правила безопасности
1. Только чтение: не отправлять реальные формы на рабочем сайте (заявки уйдут менеджерам/в CRM). Формы —
   на тестовой копии, либо с явного согласия пользователя с пометкой «ТЕСТ» в полях, либо проверка до отправки.
2. Нагрузка: обход ссылок с concurrency 2–4, без стресс-тестов.
3. Браузерные MCP (chrome-devtools-mcp, Playwright) и Claude in Chrome подключаются пользователем и запускаются
   только с его разрешения; для Claude in Chrome — отдельный профиль браузера без админ-сессий.
4. Внешние сервисы (W3C validator) получают HTML публичных страниц — это допустимо; закрытые страницы туда не отправлять.

## Инструменты (минимальный набор без дублей; версии закреплены)
| Задача | Инструмент |
|---|---|
| Консоль, сеть, скриншоты, адаптивность, трассы производительности, Lighthouse (a11y/SEO/best practices) | MCP `chrome-devtools` (`chrome-devtools-mcp@1.10.1 --isolated --no-usage-statistics --no-performance-crux`) |
| Пакетные отчёты производительности (mobile/desktop) | `npx -y lighthouse@13.5.0 <url> --output=json --output=html` |
| Битые ссылки (рекурсивно) | `npx -y linkinator@8.1.0 <url> --recurse --concurrency 3 --format json` |
| Валидность HTML | W3C Nu: `curl -s -H "Content-Type: text/html; charset=utf-8" --data-binary @page.html "https://validator.w3.org/nu/?out=json"` |
| Сценарии форм, кросс-браузер (опционально) | MCP Playwright `@playwright/mcp@0.0.83` |
Запуск `npx` требует подтверждения пользователя (хук безопасности спросит).

## Порядок
1. Список проверяемых URL: изменённые страницы + главная + по одной странице каждого раздела каталога + контакты.
2. Разрешения: 375×667, 414×896, 768×1024, 1366×768, 1920×1080 — скриншоты и проверка вёрстки (наложения,
   горизонтальная прокрутка, читаемость, меню, popup).
3. Консоль JS и сетевые ошибки (404/500, смешанный контент) на каждой странице.
4. Ссылки и документы (PDF деклараций/паспортов скачиваются, открываются, не 404).
5. Формы: валидация, сообщения, согласие на обработку ПДн, капча — без реальной отправки (см. правила).
6. Производительность: Lighthouse mobile/desktop; LCP/CLS/INP (полевые данные — Яндекс.Метрика/CrUX при наличии);
   вес изображений, форматы (WebP/AVIF), lazy-loading.
7. SEO-база: title/description/H1, canonical, robots, sitemap, Open Graph, schema.org, alt.
8. Доступность: контраст, фокус, подписи полей, alt, порядок заголовков.
9. Отчёт по `references/qa-report-template.md`; блокеры — сразу пользователю.

## Критерии «можно выпускать»
Нет блокеров (сломанная вёрстка на мобильных, неработающая форма/меню, ошибки JS, 404 на ключевых ссылках,
регресс Lighthouse Performance > 10 пунктов к прошлому замеру). Остальное — в бэклог с приоритетом.
