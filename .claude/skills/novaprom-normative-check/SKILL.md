# Нормативная проверка (НОВАПРОМ)

## Жёсткие правила
1. **Не выдумывать нормы, номера пунктов и формулировки.** Цитата требования — только из текста, который
   есть у пользователя или найден в официальном/надёжном источнике в этой сессии. Если текста нет —
   писать «текст документа не найден / не предоставлен; требование указано по вторичному источнику X» или
   «требует проверки по первоисточнику».
2. Каждая ссылка: обозначение + год/редакция + раздел/пункт (когда возможно) + статус (действует / отменён /
   заменён на …, дата проверки, источник статуса).
3. Классифицировать каждое требование:
   - **ОБЯЗАТЕЛЬНОЕ (закон/ТР)** — ТР ТС/ЕАЭС, федеральные законы, ФНП;
   - **ОБЯЗАТЕЛЬНОЕ (по договору)** — ТЗ, ОЛ, ОТТ заказчика, условия договора;
   - **ДОКАЗАТЕЛЬНАЯ БАЗА** — стандарты из перечней к ТР (применение добровольное, но даёт презумпцию соответствия);
   - **ОБЯЗАТЕЛЬНОЕ (ссылка)** — стандарт стал обязательным, потому что на него ссылается обязательный документ;
   - **РЕКОМЕНДАЦИЯ** — прочее (справочники, рекомендации, «как правило»).
   Обоснование классификации — ссылкой, а не «обычно так».
4. Конфиденциальность: ОТТ и документы заказчиков не отправлять во внешние сервисы (Gamma, Canva, онлайн-OCR,
   переводчики) и не коммитить в публичный репозиторий. Работать локально.
5. Изменения в действующих документах предприятия — только как предложения (redline/таблица замечаний),
   сами файлы не перезаписывать без разрешения.

## Проверка актуальности
Порядок источников (официальные — первыми): каталог/фонд стандартов Росстандарта; официальные сайты ЕЭК
(тексты ТР ТС/ЕАЭС и перечни стандартов к ним); официальные публикации актов (publication.pravo.gov.ru);
профессиональные справочные системы (Кодекс/Техэксперт — docs.cntd.ru) как вторичный источник статуса.
Подробнее и типовые замены устаревших документов — `references/sources-and-replacements.md`.

## Порядок работы
1. Инвентаризация: список всех документов и ссылок в проверяемом документе (таблица: ссылка как написано →
   правильное обозначение → статус → замена).
2. Извлечение требований из «старших» документов (ТР, ОТТ, ТЗ/ОЛ) в реестр:
   `ID | документ | пункт | цитата | тип | к чему относится`.
3. Сопоставление с проверяемым документом (ТУ, ПМИ, паспорт, РЭ, КД, ТКП): матрица соответствия
   `ID требования | где в нашем документе | соответствует / частично / нет / н.п. | замечание | предлагаемая правка`.
4. Противоречия: между документами одного уровня и между уровнями. Для каждого — какой документ имеет
   приоритет и почему (иерархия: закон/ТР > договор (ТЗ/ОТТ/ОЛ) > стандарты/ТУ > внутренние документы —
   если договор не устанавливает иное).
5. Итог: краткий вывод, критические несоответствия (блокируют поставку/сертификацию), значимые, редакционные;
   список вопросов к заказчику.

Шаблоны таблиц — `references/templates.md`. Для ОТТ Транснефти — навык `novaprom-transneft`.
