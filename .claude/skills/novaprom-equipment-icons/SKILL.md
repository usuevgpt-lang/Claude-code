# Иконки оборудования НОВАПРОМ (NOVAPROM ICON DESIGN SYSTEM)

Спецификация стиля — `references/icon-design-system.md`; прочитай её перед рисованием.
- Машиночитаемая версия — `references/icon-spec.json`.
- Эталоны (14 плиток с сайта) — `references/reference-icons/`.
- Общие SVG-инструменты (проверка безопасности, рендер, лист сравнения, SVGO, экспорт) берутся из соседнего скилла `svg-icons`: `${CLAUDE_SKILL_DIR}/../svg-icons/`. Если он установлен в другом месте, используй его путь.

## Жёсткие правила
1. **Не трогать живой сайт.** Никаких правок на novaprom.ru, в MODX и в `/assets/templates/img/ico/`. Внедрение на сайт — отдельная задача через скилл `novaprom-website`, только по решению пользователя.
2. **Оригиналы неприкосновенны.**
   - Всё пишется в новую папку `./icons-work/<имя>/`: `brief.md`, `concepts/`, `preview/`, `approved/` (копия одобренного варианта), `dist/`, `export/`.
   - Эталоны и файлы пользователя только читаются.
3. **Не выдумывать технику.** На рисунке только элементы, подтверждённые источником: страница продукции компании, чертёж или 3D от пользователя, документация изготовителя. Чего нет в источнике — того нет на рисунке, либо это помечено как «уточнить».
4. **Стиль — по спецификации.** Отклонения допустимы только осознанно, с объяснением (например, отдельная версия для 106 px).
5. **Без одобрения пользователя** ничего не оптимизировать, не экспортировать «в чистовик» и не запускать `npx`. Ничего не устанавливать без согласия; Python-пакеты ставить в venv.

## Процесс для новой иконки (обязательный)
1. **Изучить реальную конструкцию.**
   - Собери источники: страницы продукции НОВАПРОМ, чертежи и фото пользователя, документацию изготовителя. Для теплообменников конструктивную часть можно сверить со скиллом `novaprom-heat-exchangers`.
   - Запиши в `icons-work/<имя>/brief.md`:
     - **видимые снаружи элементы** (корпус, днища и крышки, фланцевые разъёмы, штуцеры с положением, опоры, площадки, компенсаторы…) и источник каждого;
     - что внутреннее и на рисунке не показывается;
     - что не подтверждено.
   - Спроси пользователя о недостающем (тип аппарата, горизонтальный или вертикальный, число и положение штуцеров, тип крышек).
2. **Сделать 3–4 концепта** в `concepts/<имя>-c1.svg … -c4.svg`. Различаться должны ракурс, композиция и акценты, а не цвет: цвет фиксирован системой.
   - Холст `0 0 220 160`, `width="220" height="160"`, корень `fill="none"`.
   - Только `<path>`. Эллипсы — 4 кубическими сегментами.
   - Порядок рисования от дальнего к ближнему; тела залиты `#F5F5F5` как заслонки.
   - 2-unit — силуэт и опоры (≈ 20–30 % длины линий); 1-unit — детали, стыки, 3–8 линий кривизны.
   - `stroke-linejoin="round"`, `stroke-miterlimit="10"`, linecap по умолчанию (butt).
   - Перспектива трёхчетвертная: вертикали вертикальны, уходящие рёбра 4–12°, торцы-эллипсы с отношением осей ≈ 0,45–0,65.
   - Центр габарита — в центре холста по горизонтали; объект ≈ 75–90 % ширины.
   - Бюджет: 20–60 путей, 50–200 узлов.
   - Ближайшие эталоны для горизонтальных аппаратов — ico-tile-10, -11, -13. Пример построения — `references/examples/heat-exchanger-concept-draft.svg`.
3. **Проверить и сравнить с эталонами:**
   ```bash
   SVGI="${CLAUDE_SKILL_DIR}/../svg-icons/scripts"
   python3 "$SVGI/check_svg.py" icons-work/<имя>/concepts/                       # безопасность и структура
   python3 ${CLAUDE_SKILL_DIR}/scripts/check_novaprom_style.py icons-work/<имя>/concepts/   # стиль: PASS/WARN/FAIL
   python3 "$SVGI/render_preview.py" sheet "icons-work/<имя>/concepts/*.svg" \
       "${CLAUDE_SKILL_DIR}/references/reference-icons/ico-tile-10__*.svg" \
       "${CLAUDE_SKILL_DIR}/references/reference-icons/ico-tile-11__*.svg" \
       --sizes 106 239 --out icons-work/<имя>/preview/sheet-106-239.png --title "<имя>: концепты и эталоны"
   ```
   - На Windows: `py -3` вместо `python3`, вместо `$SVGI` — полный путь к `svg-icons\scripts`.
   - FAIL исправить всегда.
   - WARN объяснить: у эталонов тоже есть WARN, это задокументированные несоответствия (раздел 6 спецификации).
   - Для меню: `--family dropdown`, холст 65×50, лист с `--sizes 57 --background "#1C1C1C"`.
4. **Проверить читаемость в реальном размере.**
   - Открой лист через Read.
   - На 106 px силуэт должен узнаваться, а линии 1 unit (0,48 px) не должны превращаться в серую кашу; иначе упростить.
   - На 239 px детали должны читаться.
   - Дополнительно проверь `--dpr 2` (Retina).
   - Сравни визуальный вес с соседними плитками: «чернила» ≈ 25–52 % холста, медиана 36,6 %.
5. **Показать пользователю** 1–2 лучших варианта.
   - Приложи лист сравнения и таблицы проверок.
   - Перечисли, какие элементы взяты из какого источника и что осталось «уточнить».
   - Править по замечаниям в новых файлах (`-c2-r1.svg`).
6. **После одобрения — оптимизировать** по конвейеру `svg-icons`.
   - Спроси разрешение на `npx svgo@4.1.0`.
   - Команда: `npx svgo@4.1.0 --config "${CLAUDE_SKILL_DIR}/../svg-icons/svgo.config.mjs" -f icons-work/<имя>/approved -o icons-work/<имя>/dist`.
   - Затем снова `check_svg.py` и лист сравнения. `mergePaths` уменьшает число путей при той же картинке: стиль проверяй по исходнику, вид — по рендеру `dist`.
7. **Подготовить веб-форматы** по запросу:
   ```bash
   python3 "$SVGI/render_preview.py" render icons-work/<имя>/dist/<имя>.svg --sizes 106 239 --dpr 2 --webp --out-dir icons-work/<имя>/export
   ```
   - Размеры брать по месту показа: плитка ≈ 106 и 239 px CSS, меню 57 px.
   - Фавиконки и OG-картинки — скилл `web-assets`.
   - Итог: список файлов, размеры, оставшиеся WARN, что нужно для внедрения (отдельной задачей).

## Первая плановая иконка: «Теплообменное оборудование» (кожухотрубный теплообменник)
**Видимые элементы.** Это кандидатный список; **подтвердить по чертежам пользователя**, тип аппарата и число ходов не угадывать.

| Элемент | Что показать | Что уточнить по чертежу |
|---|---|---|
| Кожух (обечайка) | Длинный цилиндр, 2-unit силуэт, линии кривизны | Горизонтальный или вертикальный, соотношение длины и диаметра |
| Две камеры или крышки | Передняя распределительная камера с крышкой; задняя камера, днище или крышка кожуха | Тип по исполнению: неподвижные решётки / компенсатор / плавающая головка / U-трубы. Крышка плоская на болтах или эллиптическое днище |
| Фланцевые разъёмы | Камера—кожух (решётка между фланцами), крышка—камера; стопка эллипсов | Сколько разъёмов видно, есть ли разъём сзади |
| Штуцеры | Трубное пространство на камере (при 2 ходах — оба на передней), межтрубное — на кожухе; шейка и фланец | Количество, сторона (верх, низ, бок), примерные позиции |
| Седловые опоры | 2 опоры, 2-unit, как в ico-tile-10 | Для вертикального аппарата — лапы или опора-юбка |
| Прочее (по месту) | Компенсатор на кожухе, строповые элементы, дренаж и воздушник | Показывать, только если есть на чертеже и читается на 106 px |
| Не показывать | Трубный пучок, перегородки, решётки изнутри | Внутренние элементы; разрезы в системе не используются |

- Названия исполнений сверить с действующим стандартом на кожухотрубные аппараты (ГОСТ 31842 и др. — проверить применимость).
- `references/examples/heat-exchanger-concept-draft.svg` — **ЧЕРНОВИК, не утверждён.**
  - Демонстрация конвейера, сделана без чертежей: передняя камера с плоской крышкой, задняя камера с эллиптическим днищем, 2 разъёма, 2+2 штуцера, 2 седла. Позиции штуцеров и типы крышек — заглушки.
  - Проходит `check_svg.py` (0 ошибок) и `check_novaprom_style.py`: 20 PASS, 0 WARN, 0 FAIL — 34 пути и 127 узлов, доля 2-unit 35,5 %, эллипсы 0,457, «чернила» 36,7 %.
  - Использовать только как образец построения, не как готовую иконку.

## Зависимости проверки стиля
- Базовые проверки работают на чистом Python 3: холст, палитра, толщины, стыки, запрещённые элементы, число путей и узлов.
- Геометрия (центрирование, поля, доля 2-unit, эллипсы, проекция) требует `svgelements`. Без него эти строки получают статус SKIP с причиной.
- «Чернила» требуют `cairosvg` (или `resvg` в PATH) и `Pillow`.
- Установка в venv, только с согласия:
  - Linux: `python3 -m venv .venv && .venv/bin/pip install svgelements cairosvg "Pillow>=12,<13"`
  - Windows: `py -3 -m venv .venv; .\.venv\Scripts\pip install svgelements cairosvg "Pillow>=12,<13"`. CairoSVG на Windows требует Cairo DLL; проще `scoop install resvg`.
